честно делит **«работает прямо сейчас»** и **«требует боевого окружения»**.

## 2. Запуск и тест БЭКЕНДА (работает сейчас)

### 2.1. Установка зависимостей
```bash
cd symbiont_build/backend
python3 -m venv .venv && source .venv/bin/activate     # опционально, но рекомендуется
pip install -r requirements.txt
```

### 2.2. Автотест одной командой (рекомендуется первым)
```bash
python smoke_test.py
```
Эталонный вывод (всё уже проверено):
```
  [OK] анонимный аккаунт создан (200)
  [OK] выдан непрозрачный токен
  [OK] план по умолчанию free
  [OK] неверный ключ отвергнут (422)
  [OK] без токена запрещено (401)
  [OK] ключ выпущен админом (200)
  [OK] выпуск без админ-токена запрещён (403)
  [OK] ключ погашен (200, план pro)
  [OK] повтор тем же аккаунтом идемпотентен
  [OK] чужой аккаунт получает отказ (409)
  [OK] манифест отдан (200)
  [OK] подпись манифеста валидна
  [OK] 304 при актуальной версии
  [OK] диалог поддержки ведётся (>=3 сообщений)

РЕЗУЛЬТАТ: все проверки пройдены ✔
```
Код возврата `0` — успех. Тест поднимает приложение через `TestClient`, сервер
запускать отдельно не нужно.

### 2.3. Запуск живого сервера
```bash
# по желанию задать свой админ-токен:
export SYMBIONT_ADMIN_TOKEN="придумай-секрет"
uvicorn server:app --reload
```
- Swagger-документация и ручной вызов всех эндпоинтов: `http://127.0.0.1:8000/docs`
- При первом старте создаётся `signing.key` (ключ подписи). Не коммитить в git.

### 2.4. Ручная проверка через curl (по шагам)
```bash
# 1) анонимный аккаунт → запомнить token
curl -s -X POST localhost:8000/v1/account/anon \
  -H 'content-type: application/json' -d '{"label":"гость"}'

# 2) выпустить ключ (нужен админ-токен)
curl -s -X POST localhost:8000/v1/admin/issue \
  -H 'x-admin-token: demo-admin-token' \
  -H 'content-type: application/json' -d '{"plan":"pro","grant_days":30,"uses":1}'

# 3) погасить ключ (TOKEN из шага 1, CODE из шага 2)
curl -s -X POST localhost:8000/v1/key/redeem \
  -H "authorization: Bearer <TOKEN>" \
  -H 'content-type: application/json' -d '{"code":"<CODE>"}'

# 4) подписанный манифест (узлы + правила + категории)
curl -s "localhost:8000/v1/manifest" | head -c 500

# 5) поддержка: написать сообщение и прочитать ветку
curl -s -X POST localhost:8000/v1/support/message \
  -H "authorization: Bearer <TOKEN>" \
  -H 'content-type: application/json' \
  -d '{"text":"YouTube не открывается","diag":{"consent":true,"report":"reachable_but_tls_reset"}}'
curl -s localhost:8000/v1/support/thread -H "authorization: Bearer <TOKEN>"
```

### 2.5. Ожидаемые коды ответов (чек-лист)
| Действие | Ожидаемо |
|---|---|
| Создать аккаунт | `200` + `token` |
| Погасить неверный ключ | `422 key_invalid` |
| Запрос без `Authorization` | `401` |
| Выпуск ключа без админ-токена | `403` |
| Погасить валидный ключ | `200` + `plan/paidUntil` |
| Тот же ключ тем же аккаунтом | `200 idempotent:true` |
| Тот же ключ другим аккаунтом | `409 key_already_redeemed` |
| Манифест при `since` = текущая версия | `304` |

## 3. Запуск и тест КЛИЕНТА (работает сейчас, на моке)

### 3.1. Установка и запуск
```bash
cd symbiont_build
flutter pub get
flutter run            # выбрать устройство: Chrome / desktop / эмулятор
```
Если список пуст — `flutter devices`; для веба `flutter run -d chrome`, для
десктопа включить `flutter config --enable-<platform>-desktop`.

### 3.2. Ручной чек-лист UI (что прокликать)
- **Защита:** нажать круг → «Подключение…» → «Защищено», метрики ожили (пинг/потери/Reality);
  нажать снова → «Не защищено». Переключить режимы охвата (Умный/Вся система/Только выбранное/Выключено).
- **Узлы:** поиск страны; «Самый быстрый» / «Случайный»; выбор узла подсвечивает карточку; звезда — избранное.
- **Анализ:** «Запустить анализ» → список сервисов с цветными категориями
  (Нужно напрямую / Нужен пробой / Ускоряем / Можно напрямую); тап по кнопке действия меняет его; «Принять рекомендуемое».
- **Аккаунт:** изменить «Метку»; «Устройства — без ограничения»; ввести ключ (≥12 символов) → «Активировать» → план станет Pro; «Скопировать» код рефералки.
- **Поддержка:** написать сообщение → придёт ответ; «Починить интернет» → системная диагностика; «Пожаловаться на сервер» → подтверждение.
- **Настройки** (шестерёнка): тумблеры рекламы/трекеров/фишинга/Стоп-крана; сегмент DNS (DoH/DoT/DoQ/ODoH).
- **Словарь** (книга): поиск; тап по термину раскрывает объяснение; видна пометка «также: …».
- **Языки:** переключатель RU/EN — весь интерфейс меняется (бренд «Симбионт» остаётся).

### 3.3. Анализ кода без устройства
```bash
flutter analyze        # статический анализ (ожидаемо без ошибок)
flutter test           # если добавите тесты в test/
```

> Примечание: клиент работает на `MockEngine` — подключение и метрики
> **симулированы**. Это ожидаемо: реальный туннель появляется после нативного шага (раздел 5).

## 4. Связать клиент с бэкендом (следующий маленький шаг)

Сейчас клиент и бэкенд независимы. Чтобы клиент брал узлы/правила с сервера:
1. Поднять бэкенд (раздел 2.3).
2. В клиенте добавить HTTP-клиент к `GET /v1/manifest`, **проверять подпись Ed25519**
   (открытый ключ вшить заранее; для разработки — `GET /v1/pubkey`).
3. Маппить `nodes`/`rules` манифеста в типы `NodeInfo`/`RoutingRule` и отдавать движку.
Контракт ответов — `backend/API.md`; схема — `schema/manifest.schema.json`.

## 5. Встроить ГОТОВЫЙ движок (превращает каркас в боевой VPN)

Полная пошаговая инструкция — в `NATIVE_INTEGRATION.md`. Кратко:
1. Подключить libbox (сборка Sing-box): Android `.aar`, iOS `.xcframework`.
2. Android: `VpnService` + `MethodChannel('symbiont/engine')` → connect/disconnect/статус.
3. iOS/macOS: Packet Tunnel Provider + App Group + entitlements.
4. В `lib/main.dart` заменить `AppState(MockEngine())` → `AppState(SingboxEngine())`.
5. Конфиг sing-box собирать из подписанного манифеста (узел + протокол).

**Тест боевого движка (после шага):**
- подключение реально меняет внешний IP (проверить на сайте «какой у меня IP»);
- kill-switch: при разрыве туннеля трафик блокируется;
- split-tunneling: банк/госуслуги идут напрямую (на iOS — по доменам/IP);
- заблокированный ресурс открывается с режимом «Пробой».

> Туннель/протоколы/пробой выполняет **готовый Sing-box**; наш код — обвязка ОС,
> канал и сборка конфига. Новый обходной движок мы не пишем.

## 6. Перед боевым запуском (чек-лист продакшена)

- [ ] Свой `SYMBIONT_ADMIN_TOKEN`, `signing.key` — в секрет-хранилище (sops/age), не в git.
- [ ] Заменить in-memory хранилища бэкенда на БД (атомарность погашения — уникальный индекс).
- [ ] HTTPS/обратный прокси, rate-limit (`429`), CORS.
- [ ] Реальные узлы (Server-in-a-Box, тома IV–V), подписанный каталог, canary-раскатка.
- [ ] Подпись приложений: Android keystore; iOS — профили/entitlements NetworkExtension.
- [ ] Аттестация устройства (App Attest / Play Integrity) для free/триала; биллинг-провайдер.
- [ ] ES/DE в `i18n/strings.dart` (1:1 с RU/EN; полный набор есть в HTML-прототипе).
- [ ] Юридическая рамка и хостинг — по томам I, IV (юрисдикция, no-logs честно).

## 7. Если что-то не так (быстрая диагностика)

| Симптом | Причина / решение |
|---|---|
| `pip install` падает на cryptography | обновить pip: `pip install -U pip`; поставить build-tools ОС |
| `uvicorn: command not found` | активировать venv или `python -m uvicorn server:app` |
| `403` на `/v1/admin/issue` | неверный `x-admin-token` (по умолчанию `demo-admin-token`) |
| `401` на эндпоинтах | нет/просрочен `Authorization: Bearer <token>` |
| `flutter run` не видит устройств | `flutter devices`; `-d chrome`; включить desktop-таргет |
| google_fonts без сети | шрифт подтянется при наличии сети; иначе будет системный |
| Метрики «ненастоящие» | это `MockEngine` — ожидаемо до нативного шага (раздел 5) |
