# Симбионт (symbiont_build) — аудит архитектуры и внесённые правки (2026-06-26)

## Проверено и реально работает
- **Бэкенд (FastAPI):** smoke 14/14 — аккаунты, ключи (Ed25519, идемпотентно),
  подписанный манифест, поддержка. Запускается в реальности.
- **Генератор узла (server/gen_server.py):** даёт валидный sing-box 1.13 конфиг на
  3 протокола (Reality 443/tcp, Hysteria2 8443/udp, SS2022 9443/tcp). Приватный
  Reality-ключ остаётся в secrets.json и НЕ попадает в манифест (publish_nodes.py
  это проверяет). install.sh ставит официальный sing-box + systemd.
- **Подпись манифеста:** клиент реально верифицирует Ed25519; канонизация JSON на
  Dart и Python — БАЙТ-В-БАЙТ идентична (проверено на реальном манифесте) → подпись
  сходится между клиентом и сервером.
- **Сетевой анализ:** настоящий (TCP-сокеты, ip-api ASN, детект блокировок, cloudflare speed).
- **Структура Dart:** 32 файла, все скобки сбалансированы; контракт SymbiontEngine
  (15 методов) реализован во всех 3 движках; i18n RU/EN на паритете.
- **Выбор движка:** корректные гарды — на Windows/Linux/macOS с бинарниками реальный
  DesktopEngine, иначе (мобайл/web/без бинарников) MockEngine.

## ИСПРАВЛЕНО (2 критичных бага, ломавших основной VPN)
Несовпадение клиентского конфига с серверным — VLESS требует совпадения транспорта,
иначе рукопожатие рвётся, а `sing-box check` это пропускает (валидно синтаксически):

1. **VLESS+Reality:** клиент в `singbox_config.dart` ВСЕГДА добавлял `transport:http`,
   а сервер из gen_server.py — голый Reality поверх RAW-TCP. → Основной протокол не
   соединялся. **Фикс:** для sing-box-узлов (xrayCore=false) transport НЕ добавляется
   (raw TCP, как на сервере); xhttp остаётся только для xray-узлов. tls.fragment сохранён.
2. **Hysteria2:** клиент ВСЕГДА слал `obfs:salamander`, сервер obfs не настраивает.
   → Резервный протокол не соединялся. **Фикс:** obfs шлётся только если узел реально
   его включил (manifest даёт пароль obfs).

После правок сверка клиент↔сервер по всем 3 протоколам: ✅ совпадает.

## Что отсутствует (по приоритету для максимизации показателей)
- 🔴 Нет развёрнутого VPS → экран «Узлы» пуст. Код узла готов — нужен один сервер.
- 🔴 Мобильные движки (singbox_engine.dart) — заглушки `TODO: native` (Android VpnService/

- 🟡 Бэкенд in-memory: нет БД/биллинга/TLS-хостинга; ключ подписи в проде надо прибить

- 🟡 Аттестация/анти-абьюз — эндпоинт-заглушка.
- 🟡 Свой движок (symbiont-engine) пока не интегрирован — отдельная задача.

## Доделано «всё до VPS» (2026-06-26, заход 2)

Цель: чтобы осталось только купить VPS. Реализовано:

1. **server/bootstrap_vps.sh** — ОДНА команда на чистом Ubuntu поднимает ВЕСЬ сервис:
   узел (sing-box, 3 протокола) + бэкенд (FastAPI, systemd на 0.0.0.0:8000) + связывает
   их в подписанный манифест + печатает ключ и команду сборки клиента. Идемпотентно.
2. **Клиент собирается под конкретный VPS** — kDefaultBaseUrl/kTrustedPubKey переведены
   на String.fromEnvironment (--dart-define=SYMBIONT_BASE_URL / SYMBIONT_PUBKEY).
   Dev-дефолты не изменились.
3. **server/selftest_pipeline.py** — сквозной тест ВСЕГО конвейера без VPS (узел на
   127.0.0.1): gen → publish → манифест → подпись → сверка клиент↔сервер. 15/15 ✔.
4. **Фикс 3 (Hysteria2 TLS):** сервер использует самоподписанный серт, клиент его не
   принимал → Hysteria2 упал бы. Добавлен insecure:true (аутентификация Hysteria2 — по
   паролю, не по серту; узел с настоящим сертом выключает через insecure:false в манифесте).
5. **DEPLOY.md** — пошагово «купил VPS → одна команда → собрал клиент».

Итог: все три бага совместимости клиент↔сервер закрыты (Reality, Hysteria2, +самоподпись),
конвейер доказан локально, развёртывание — одна команда.

## Control-plane манифеста (2026-06-26, заход 3 — реализация блюпринта)

Реализован первый срез «идеального сервиса» из блюпринта — управляющий слой манифеста
(фундамент горячих обновлений и управления флотом). Всё проверяемо без VPS.

1. **Роли узла** (`gen_server.py --role node|relay`): node→roles=['edge'] (точка выхода),
   relay→roles=['relay']+whiteIp (обход CIDR-whitelist, клиент его прячет из списка).
2. **Юридический предохранитель РФ:** gen_server и publish_nodes ОТКАЗывают в публичном
   exit-узле с code=RU (оператор = «контролёр»: СОРМ, ОРИ/FGIS, ст. 13.52/13.53 КоАП,
   отягчающее по ст. 63 УК). relay в РФ разрешён с предупреждением.
3. **Canary-выкатка** (1%→5%→25%→100%): поле `rollout` в ПОДПИСАННОМ теле манифеста;
   операторский рычаг `POST /v1/admin/rollout`; клиент сам решает, попал ли в волну, по
   стабильному FNV-1a-хешу токена. Распределение проверено: 0.9/5.1/24.6/100%.
4. **Монотонность версии:** клиент хранит appliedManifestVersion и применяет только
   строго бОльшую (защита от отката на старый подписанный манифест). Откат = roll-forward
   на новую версию с прежним содержимым.
5. **Детерминированная версия бэкенда:** убран баг двойного инкремента (смена rollout
   больше не двигает версию ложно).

Файлы: backend/server.py, server/gen_server.py, server/publish_nodes.py,
lib/api/api_client.dart, lib/store.dart, lib/state/app_state.dart,
server/bootstrap_vps.sh (+--role). Тест: server/selftest_controlplane.py (18/18).

Регрессия: бэкенд 14/14, конвейер 15/15, control-plane 18/18, Dart сбалансирован.

## Заход 4 — четыре среза блюпринта (2026-06-26)

Реализованы все четыре намеченных среза, всё автоматическое и проверяемое без VPS.

**1. Файловая персистентность бэкенда** (backend/persist.py — атомарная запись):
аккаунты, диалоги поддержки и реестр ключей переживают рестарт (accounts.json,
threads.json, keys_registry.json). Авто-загрузка на старте, авто-сохранение при
мутациях. На масштаб — заменить на SQLite, интерфейс тот же.

**2. Саморегистрация узла** (POST /v1/node/register): узел сам вписывается в манифест,
подписываясь HMAC-SHA256 на секрете оператора (NODE_SECRET) — без ручного publish_nodes.
Бэкенд проверяет подпись (анти-Sybil), юр-предохранитель (РФ-exit→403), upsert в
nodes.json, пересборка+переподпись манифеста. server/register_node.py + bootstrap
--register-to/--node-secret: новый VPS появляется в сети одной командой.

**3. Детект «16 КБ занавеса»** (lib/net/curtain.dart): классификатор clear/curtain/
blocked/slow/partial + проба Probe.probeCurtain (замер заморозки потока). Запускается
автоматически в конце анализа сети; при curtain/slow — АВТО-увод трафика через relay.

**4. Relay-цепочка**: relay-узлы парсятся отдельно (Manifest.relays, в списке UI их нет),
контракт SymbiontEngine.setRelay (no-op по умолчанию), DesktopEngine строит detour через
relay в sing-box-конфиге. AppState при детекте занавеса сам ставит relay в движок.

Файлы: backend/{persist.py,server.py,keys.py}, server/{register_node.py,bootstrap_vps.sh},
lib/net/{curtain.dart,probe_io.dart,probe_web.dart}, lib/api/api_client.dart,
lib/engine/{engine.dart,desktop_engine_io.dart,mock_engine.dart,singbox_engine.dart},
lib/state/app_state.dart.

Тесты: selftest_persistence.py (11/11), selftest_client_logic.py (14/14).
ПОЛНАЯ РЕГРЕССИЯ: smoke 14 + pipeline 15 + controlplane 18 + persistence 11 +
client_logic 14 = 72 проверки ✔, Dart сбалансирован, без регрессий.
