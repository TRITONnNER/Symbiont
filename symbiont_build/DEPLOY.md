# Симбионт — развёртывание: «купил VPS → сервис работает»

Всё, что можно было сделать до покупки сервера, уже сделано и проверено локально
(`python3 server/selftest_pipeline.py` — 15/15). Ниже — что осталось: **купить VPS и
выполнить одну команду**.

## Перед покупкой можно проверить ВЕСЬ конвейер (без сервера)

```bash
cd backend && pip install -r requirements.txt        # один раз
python3 server/selftest_pipeline.py                  # генерит узел → связывает → подписывает → сверяет клиент↔сервер
```
Зелёный результат = после VPS всё поднимется. Этот тест гоняет ровно те шаги, что
`bootstrap_vps.sh` делает на сервере (узел на 127.0.0.1 вместо реального IP).

## Шаг 1. Купить VPS

Любой провайдер, **Ubuntu 22.04 / 24.04**, 1 vCPU / 1 ГБ. Нужен публичный IP и root по SSH.
В панели провайдера (если там свой firewall) открой: `443/tcp`, `8443/udp`, `9443/tcp`, `8000/tcp`.

## Шаг 2. Одна команда — поднимается ВЕСЬ сервис

```bash
scp -r symbiont_build/ root@<IP>:/root/
ssh root@<IP>
cd /root/symbiont_build/server
sudo bash bootstrap_vps.sh --code NL --country Netherlands --sni www.microsoft.com
```

`bootstrap_vps.sh` сам, идемпотентно:
1. определяет публичный IP сервера;
2. генерирует узел (Reality/Hysteria2/SS2022) + секреты;
3. ставит sing-box, поднимает узел (systemd, автозапуск);
4. разворачивает бэкенд (FastAPI) в venv как systemd-сервис на `0.0.0.0:8000`;
5. **связывает** узел с бэкендом → манифест отдаёт этот узел, подписанный Ed25519;
6. открывает порты в ufw;
7. печатает адрес бэкенда, **прибиваемый ключ подписи** и готовую команду сборки клиента.

В конце увидишь блок вида:
```
Бэкенд:  http://<IP>:8000   (манифест уже содержит этот узел)
Ключ подписи (прибей в клиент): <ed25519-base64>
  flutter build windows --release \
    --dart-define=SYMBIONT_BASE_URL=http://<IP>:8000 \
    --dart-define=SYMBIONT_PUBKEY=<ed25519-base64>
```

## Шаг 3. Собрать клиент «из коробки на твой VPS»

Скопируй напечатанную команду. Тогда приложение:
- по умолчанию смотрит на твой бэкенд (`SYMBIONT_BASE_URL`) — онбординг можно проскочить;
- доверяет **только** твоему ключу подписи (`SYMBIONT_PUBKEY`) и не качает его по сети.

Без флагов (dev-сборка) клиент остаётся на `http://127.0.0.1:8000` и берёт ключ по сети —
поведение не изменилось, удобно для локальной разработки.

## Добавить ещё узел (когда захочешь масштабироваться)

Повтори Шаг 2 на новом VPS **с тем же бэкендом**: запусти `bootstrap_vps.sh --no-backend`
на новом сервере (поднимет только узел), потом на машине с бэкендом собери узлы вместе:
```bash
python3 server/publish_nodes.py node1.json node2.json --out /opt/symbiont/backend/nodes.json
systemctl restart symbiont-backend
```
Клиент подтянет новые узлы из подписанного манифеста автоматически.

## Мультиузел и автоматика (заход 4)

**Добавить узел на ОТДЕЛЬНОМ VPS** (саморегистрация, без ручного publish_nodes):
```bash
# на новом VPS — только узел, сам зарегистрируется на твоём бэкенде:
sudo bash bootstrap_vps.sh --no-backend \
  --code FI --country Finland \
  --register-to http://<IP_БЭКЕНДА>:8000 \
  --node-secret <ТВОЙ_СЕКРЕТ_ОПЕРАТОРА>
```
Узел появится у всех клиентов автоматически (подписанный манифест обновится).
Секрет зачисления узлов задаётся на бэкенде через env `SYMBIONT_NODE_SECRET`
(bootstrap прокидывает его в systemd-юнит). Если не задан — генерируется в
`secrets.json` (см. раздел «Секреты в проде» ниже); для мультиузла удобнее задать
его явно, чтобы один и тот же секрет был у бэкенда и при запуске узлов.

**Canary-выкатка** (плавное обновление с защитой):
```bash
curl -X POST http://<IP>:8000/v1/admin/rollout \
  -H 'x-admin-token: <АДМИН_ТОКЕН>' -H 'content-type: application/json' \
  -d '{"percent": 5}'        # 5% клиентов получат новую версию; потом 25, 100
```

**Что теперь автоматическое:** состояние переживает рестарт; узлы регистрируются сами;
клиент при анализе сам детектит «16 КБ занавес» и уводит трафик через relay; обновления
манифеста монотонны и катятся волнами с защитой от отката.

## Секреты в проде (ОБНОВЛЕНО — больше нет предсказуемых дефолтов)

Сервер берёт секреты так: **env → `secrets.json` → генерация**. Если переменных
окружения нет, сервер при первом старте **сам сгенерирует** случайные секреты и
сохранит в `secrets.json` (стабильны между рестартами). `secrets.json` уже в
`.gitignore` — **не коммить, держи только на сервере**.

Задействованы: `SYMBIONT_ADMIN_TOKEN` (админ-операции: гранты, выпуск ключей,
rollout), `SYMBIONT_NODE_SECRET` (секрет **зачисления** узлов), `SYMBIONT_WHEEL_SEED`
(сид колеса), `SYMBIONT_ALIAS_SECRET` (HMAC алиасов — задать в проде обязательно,
иначе хеши алиасов несопоставимы между перезапусками без `secrets.json`).

**Вариант А — задать самому (рекомендуется для прода):**
```bash
export SYMBIONT_ADMIN_TOKEN=$(openssl rand -base64 24)
export SYMBIONT_NODE_SECRET=$(openssl rand -base64 24)
export SYMBIONT_ALIAS_SECRET=$(openssl rand -base64 24)
export SYMBIONT_WHEEL_SEED=$(openssl rand -base64 24)
# пропиши их в systemd-юнит бэкенда (Environment=...) и запусти сервис
```

**Вариант Б — дать сгенерировать:** просто запусти бэкенд; затем прочитай
выданный админ-токен (он нужен тебе для грантов/ключей):
```bash
cat /root/symbiont_build/backend/secrets.json   # admin_token, node_enroll_secret, wheel_seed
```

### Пер-узловые секреты
`SYMBIONT_NODE_SECRET` теперь — секрет **зачисления**: узел подписывает им только
свою регистрацию и в ответ получает **собственный** секрет (`node_secret`),
которым дальше подписывает отчёты `/v1/node/session` (списание баланса активного
времени). Компрометация одного узла не затрагивает остальные.

## Что уже работает «из коробки» после подъёма (проверено 178 тестами)

- **Аккаунты**: регистрация по любым алиасам (ник/почта/телефон), recovery-код,
  опц. пароль (scrypt; для прода — Argon2id), анти-фрод (PoW + rate-limit /24).
- **Устройства**: список, owner-class, повышение, отзыв.
- **Экономика** (`GET /v1/config/economy`): тарифы Free/Premium/Ultimate, цены по
  регионам (₽/$/крипта-10%), методы оплаты **СБП/МИР/Visa/Mastercard/ЮMoney/крипта**.
- **Оплата** (`/v1/billing/purchase`): в dev — sandbox (авто-подтверждение); в проде
  подключается реальный `PaymentProvider` (`SYMBIONT_SANDBOX_PAY=0`).
- **Баланс активного времени**: списывается узлом только под подключением.
- **Рефералы/репутация/комбо/колесо**: всё серверное, видно в приложении.

Экономику можно править без пересборки клиента: положи рядом `backend/economy.json`
(той же формы, что отдаёт `DEFAULT_ECONOMY`) — сервер отдаст его вместо встроенной.
