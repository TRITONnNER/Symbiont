# Симбионт — серверная часть (VPN-узлы)

Этот пакет превращает **любой чистый VPS (Ubuntu 22.04/24.04)** в рабочий VPN-узел
Симбионта на трёх протоколах сразу, на одном IP:

| Протокол | Порт (по умолчанию) | Назначение |
|---|---|---|
| VLESS + Reality | `443/tcp` | основной обход DPI (маскировка под HTTPS) |
| Hysteria2 | `8443/udp` | скорость, UDP, игры |
| Shadowsocks-2022 | `9443/tcp` | резервный канал |

После развёртывания узлы автоматически появляются в подписанном манифесте бэкенда,
и клиент «Симбионт» **видит их без ручной правки** — нужно только подключиться.

---

## Что тебе понадобится

1. **VPS** (любой провайдер) — Ubuntu 22.04 или 24.04, 1 vCPU / 1 ГБ RAM достаточно для старта.
2. **Публичный IP** этого сервера (домен не обязателен — Reality работает по IP).
3. Доступ по SSH (root или sudo).

> Сервер можно купить в любой момент — пакет уже готов. До покупки можно прогнать
> генерацию локально (шаг 1), чтобы убедиться, что всё работает.

---

## Шаг 1. Сгенерировать конфиг узла (на своей машине)

В папке `server/`:

```bash
python3 gen_server.py \
  --host <ПУБЛИЧНЫЙ_IP_СЕРВЕРА> \
  --code NL --country Netherlands \
  --sni www.microsoft.com \
  --out ./out
```

- `--host` — IP (или домен) сервера.
- `--code` / `--country` — для флага и названия в приложении.
- `--sni` — «маскировочный» домен для Reality. Должен реально отвечать по 443
  (`www.microsoft.com`, `www.cloudflare.com`, `dl.google.com` — подходят).

Появятся три файла в `./out`:

| Файл | Что это | Куда идёт |
|---|---|---|
| `config.json` | серверный конфиг sing-box | на сервер (через install.sh) |
| `secrets.json` | приватные ключи и пароли | **ТОЛЬКО на сервере; НИКОМУ, не в git** |
| `manifest_node.json` | публичная запись узла | в бэкенд (шаг 3) |

> ⚠️ `secrets.json` содержит приватный Reality-ключ. Он остаётся на сервере и
> **не должен** попадать ни в манифест, ни в репозиторий. `publish_nodes.py`
> проверяет это и не даст случайно опубликовать приватный ключ.

## Шаг 2. Развернуть на сервере

Скопируй папку `server/` (вместе с `out/`) на сервер и запусти установщик:

```bash
scp -r server/ root@<IP>:/root/
ssh root@<IP>
cd /root/server
sudo bash install.sh
```

`install.sh` сам (идемпотентно, можно повторять):
1. поставит `sing-box` (официальный бинарник под архитектуру);
2. сгенерирует самоподписанный TLS-серт для Hysteria2;
3. положит `config.json` в `/etc/symbiont/`;
4. поднимет systemd-сервис `sing-box-symbiont` с автозапуском;
5. откроет порты в `ufw` (если установлен).

Проверка:
```bash
systemctl status sing-box-symbiont      # должно быть active (running)
journalctl -u sing-box-symbiont -f       # живой журнал
```

> Если используешь `ufw` и он был выключен — включи: `ufw enable`
> (убедись, что 22/tcp открыт, чтобы не потерять SSH).
> На некоторых провайдерах firewall ещё и в панели — открой там Reality TCP,
> Hysteria2 **UDP**, SS TCP.

## Шаг 3. Показать узлы клиенту (через бэкенд)

Собери записи узлов со всех серверов в один файл:

```bash
# из конкретных файлов:
python3 publish_nodes.py out/manifest_node.json --out nodes.json

# или со всех серверов сразу (если складываешь их в папку):
python3 publish_nodes.py --dir ./servers --out nodes.json
```

Положи получившийся `nodes.json` **рядом с `backend/server.py`** и перезапусти бэкенд.
Он автоматически:
- подставит реальные узлы вместо демонстрационных;
- поднимет версию манифеста (клиент увидит обновление);
- заново подпишет манифест своим Ed25519-ключом.

Клиент «Симбионт» при следующем обновлении подтянет узлы из подписанного манифеста
и покажет их на экране «Узлы». Готово — можно подключаться.

---

## Как это связано с клиентом

- Клиент берёт `transport.*` из узла манифеста (server/port/uuid/public_key/пароли)
  и подставляет в свой sing-box-конфиг (генератор `lib/engine/singbox_config.dart`).
- Приватный Reality-ключ остаётся **только** на сервере в `/etc/symbiont/config.json`.
- Каскад на клиенте: Reality (TCP) → Hysteria2 (UDP) → SS2022 (TCP) — если основной
  протокол давят, переключается на следующий.

---

## Обновление / эксплуатация

| Задача | Команда |
|---|---|
| Перезапустить узел | `systemctl restart sing-box-symbiont` |
| Посмотреть журнал | `journalctl -u sing-box-symbiont -n 100 --no-pager` |
| Проверить конфиг | `sing-box check -c /etc/symbiont/config.json` |
| Обновить sing-box | повторно `sudo bash install.sh` (скачает свежий бинарник) |
| Добавить ещё сервер | повтори шаги 1–2 на новом VPS, потом шаг 3 со всеми узлами |

---

## Безопасность и честные оговорки

- **Юрисдикция.** Узел видит весь трафик пользователя на входе в туннель (как любой VPN).
  Доверие к серверу = доверие к тебе как оператору. Для РФ-relay-узлов помни про СОРМ —
  анонимности они не дают, только обход CIDR/whitelist.
- **Самоподписанный серт Hysteria2** — норма (клиент его принимает), но это означает,
  что Hysteria2 не проходит строгую проверку CA; для маскировки этого достаточно.
- **Reality SNI** должен реально существовать и отвечать по 443 из сети сервера, иначе
  рукопожатие будет выглядеть подозрительно для DPI.
- **Это не «серебряная пуля».** Обход DPI сетезависим; конкретный протокол под конкретного
  провайдера подбирается. Каскад повышает шансы, но гарантий не даёт.
- **Нагрузка/масштаб.** Один VPS тянет десятки пользователей; для коммерции нужна
  балансировка и мониторинг (следующий этап — внешние зонды и панель).
