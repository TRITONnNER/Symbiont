# Симбионт — архитектура «всего остального»

Дизайн готов (прототип `Симбионт_приложение.html`). Этот пакет — мост от прототипа и томов I–VI к реальному проекту: **архитектура + конкретные контракты + референс-код**. Здесь нет движка обхода — он берётся готовым (Sing-box/zapret) за чистым интерфейсом.

## 2. Граница «UI ↔ движок» — главное в этом пакете

Кнопка «Подключиться» НЕ знает про протоколы. Она зовёт `SymbiontEngine`. За интерфейсом — две реализации:

| Реализация | Что делает | Когда |
|---|---|---|
| `MockEngine` | Симулирует подключение/метрики/анализ (как прототип) | Разработка и тесты UI без сети |
| `SingboxEngine` | Через `MethodChannel('symbiont/engine')` зовёт нативный **Sing-box** | Боевой клиент |

Это позволяет: (1) делать весь UI и продуктовую логику, не трогая движок; (2) подменить движок, не переписывая приложение; (3) держать обходной движок **готовым внешним компонентом**, а не нашим кодом.

---

## 3. Что готовое, а что строим сами

| Берём готовым (OSS) | Строим сами |
|---|---|
| **Sing-box** — ядро туннеля (VLESS/Reality, Hysteria2, SS-2022, WireGuard) | Клиент UI (Flutter) и ядро клиента (контракт + обёртка) |
| **zapret / byedpi** — локальный пробой DPI | Бэкенд: токены, ключи, манифест, поддержка, аттестация |
| Списки доменов (OISD, HaGeZi, угрозы) | Формат **подписанного манифеста** и правил маршрутизации |
| Нативные VPN-API ОС (VpnService / NetworkExtension) | Оркестрация флота (Server-in-a-Box роли) |
| App Attest / Play Integrity | Анти-абьюз поверх аттестации, биллинг-интеграция |

**Жёсткая граница:** новый движок обхода госфильтров мы НЕ пишем. Используем перечисленные публичные компоненты как «чёрные ящики».

## 5. Порядок сборки («что за чем»)

1. **Каркас Flutter + контракт `SymbiontEngine` + `MockEngine`.** UI из прототипа оживает на моке — продуктовая логика готова без движка.
2. **Бэкенд-MVP:** анонимный токен → погашение ключа → выдача подписанного манифеста. (`backend/`)
3. **`SingboxEngine`:** обёртка над нативным Sing-box + один протокол (Reality) + kill-switch. Тут «садится» готовый движок.
4. **Маршрутизация + split-tunneling** по платформам (Android/desktop — per-app; iOS — по адресу), правила из манифеста.
5. **Каскад протоколов** (Hysteria2, xHTTP, SS) и **умный охват** (правила/категории из манифеста + локальные пробы).
6. **Поддержка** (диалог по токену), **аттестация** (анти-абьюз free/триала), **биллинг**.
7. **Флот узлов** (Server-in-a-Box роли) + canary-раскатка манифеста.

Правила зависимостей (из тома III): DNS раньше фильтрации; маршрутизация раньше защиты банков; движок — за контрактом, а не в приложении.

---

## 6. Чего здесь НЕТ (и почему)

- **Реализации туннеля/пробоя.** Это нативный Sing-box/zapret (готовый OSS), вызываемый через границу из п.2; новый обходной движок мы не пишем.
- **Подписи приложений и entitlements** (iOS NetworkExtension, Android VpnService permission) — настраиваются в боевом окружении со своими ключами/аккаунтами разработчика.
- **Реальные серверы и секреты** — поднимаются по томам IV (защита) и V (Server-in-a-Box); здесь только схемы и контракты.
