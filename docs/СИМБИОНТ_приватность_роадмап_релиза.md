# Симбионт — приватность Server-in-a-Box: план на РЕЛИЗ

> Статус: **на тест-этапе оставляем как сейчас** (панель видит пользователей/платежи —
> удобно для отладки). Ниже — что делаем ПЕРЕД публичным релизом, чтобы сервис был
> «мы не можем видеть», а не «мы обещаем не смотреть». Для инструмента против цензуры
> это принципиально: threat-model включает принуждение оператора, злого работника и
> изъятие базы. Данных, которых нет, — не выдать.

## Что уже честно (сохранить)
- Личности нет: алиасы хранятся только как HMAC (`alias_hmac → account_id`), развернуть нельзя.
- Трафик не виден: сервер знает длительность сессии, не содержимое и не назначение.
- Связка «аккаунт↔узел↔время» эфемерна: `node_sessions` только в памяти, на диск/в логи не идёт.
- Логгер пишет лишь `метод+путь+код+время` — ни тел, ни account_id в URL.

## Что сделать на релизе (privacy mode = ВКЛ по умолчанию)

1. **Панель — агрегаты и операционка, не люди.**
   Флаг `privacy_mode` физически ОТКЛЮЧАЕТ эндпоинты пер-юзер-браузинга
   (`/v1/admin/users`, `/user/{aid}` и точечные действия) — их нет, значит нечего смотреть.
   Панель видит: узлы/здоровье, счётчики (активные/по тирам), выручку СУММАРНО, очередь
   поддержки, скидки, флаги, цены, работников, аудит.

2. **Поддержка — эфемерная, по инициативе пользователя.**
   Оператор видит только ОТКРЫТЫЕ тикеты; после решения тред авто-удаляется через N дней;
   `diag` — только по явному согласию и обезличенный. Точечный статус подписки — лишь в
   рамках тикета, с записью в аудит.

3. **Ретеншн / авто-очистка.**
   TTL на треды, ledger, устройства; детали платежей схлопываются в агрегат после окна
   возвратов. Меньше лежит — меньше можно выдать.

4. **Оплата, не связанная с использованием.**
   Крипта/слепые пополнения как ОСНОВНОЙ путь: платёжная личность не линкуется с
   аккаунтом, который тратит время (у нас уже есть крипто-скидка — сделать её приоритетной).

5. **(Глубоко) Слепые токены времени.**
   Клиент получает анонимные кредиты времени (blind-signed, как Privacy Pass) и гасит их
   на узле; узел проверяет, НЕ узнавая аккаунт; бэкенд НИКОГДА не видит аккаунт↔узел.
   Тогда неотслеживаемость — технический факт, а не обещание.

## Честный tradeoff
Пункты 1–4 — чистое улучшение, бизнес-модель не ломают. Пункт 5 меняет биллинг активного
времени (сложнее), но это единственный способ сделать «не можем видеть» доказуемым.
Анти-фрод по реф-графу — делать агрегатно/автоматически, а не «глазами по аккаунтам».

## Выбор сделан
- Тест-этап: **как сейчас** (полная панель — для отладки).
- Релиз: **privacy mode дефолтом** (эндпоинтов пер-юзер-браузинга нет → нечего смотреть) +
  ретеншн + эфемерная поддержка + крипто-путь; слепые токены времени — как цель уровня B.
