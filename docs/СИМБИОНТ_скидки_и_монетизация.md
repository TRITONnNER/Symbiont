# Симбионт — скидки, одноразовые пакеты, login-gate (реализовано + продумано)

Ответ на запрос: пробный пакет «только раз», покупки только после входа в аккаунт, и
скидки от владельца / Server-in-a-Box (как платные ключи) — с окном времени, на тариф или
на всё сразу. Всё ниже **реализовано на бэкенде и покрыто тестами** (`selftest_discounts.py` 14/14).

---

## 1. Одноразовые пакеты (пробные 20 ч)

- В каталог добавлен **`balance_20h` = 39 ₽ / $0.49**, помечен `max_per_account: 1` — покупается
  **один раз** на аккаунт. Повторная покупка → `409 purchase_limit_reached`.
- **Сделать пакет постоянным** — убрать одну строку `max_per_account` в `PRODUCTS` (тогда без ограничения).
- Механизм общий: любому продукту можно поставить лимит (`max_per_account: N`).

## 2. Login-gate (покупка только из аккаунта)

- Эндпоинт `/v1/billing/purchase` **требует токен аккаунта** — без входа покупка отклоняется
  (проверено тестом). На сайте это значит: кнопка «Купить» у гостя ведёт в **вход/регистрацию**,
  и только потом — оплата. Бэкенд это уже гарантирует, витрине остаётся показать шаг входа.

## 3. Скидки — как платные ключи (владелец / Server-in-a-Box)

Две формы, обе создаются владельцем или Server-in-a-Box (админ-токен):

- **Кампания** (без кода) — применяется **автоматически** к подходящему продукту. Витрина
  показывает «−N%» (`GET /v1/config/discounts`).
- **Код-купон** (с `code`) — пользователь вводит его при оплате. Проверяется до оплаты
  (`POST /v1/billing/discount/check`) — как проверка ключа.

Каждая скидка умеет:
- **процент** (`percent`) или **фикс-сумму** (`amount_off`);
- **объём** (`scope`): `"all"` — на всё, или `{"tiers":["ultimate"]}` / `{"products":["premium_year"]}` — точечно;
- **окно времени**: `starts_at` … `expires_at` (просроченная не применяется);
- **лимиты**: `max_uses` (всего) и `max_per_account` (напр. купон «раз на аккаунт»);
- **отзыв**: `POST /v1/admin/discount/{id}/revoke`.

### Как создаёт владелец / Server-in-a-Box

```bash
# −20% на ВСЁ (кампания, авто) до конкретной даты
curl -X POST $API/v1/admin/discount -H "X-Admin-Token: $ADMIN" -d '{
  "percent": 20, "scope": "all", "expires_at": 1767225600, "label": "Запуск −20%" }'

# −50% только на тариф Ultimate
curl -X POST $API/v1/admin/discount -H "X-Admin-Token: $ADMIN" -d '{
  "percent": 50, "scope": {"tiers":["ultimate"]}, "label": "Ultimate −50" }'

# купон SUMMER30 (−30%), один раз на аккаунт
curl -X POST $API/v1/admin/discount -H "X-Admin-Token: $ADMIN" -d '{
  "percent": 30, "code": "SUMMER30", "scope": "all", "max_per_account": 1 }'
```

**Server-in-a-Box** держит делегированный админ-токен и вызывает тот же `/v1/admin/discount` —
так «коробка» владельца раздаёт скидки централизованно. *(На будущее — можно добавить
Ed25519-подписанные discount-токены, как ключи, чтобы S-i-a-B выпускал их полностью офлайн;
инфраструктура подписи в проекте уже есть — `keys.py`.)*

### Что видит покупатель

```
purchase premium_month (199 ₽) при активной кампании −20%
 → amount 159.2 ₽, discount {percent:20, off:39.8}
purchase premium_year + код SUMMER30
 → amount 1043.0 ₽ (1490 −30%)
```

Скидки **не стакаются** — применяется одна лучшая (защита от абуза). Крипто-скидка −10 %
считается отдельно (на сумму метода `crypto`).

## 5. Что осталось по монетизации (фронт)

- **Витрина/приложение:** поле ввода купона на «Ценах» + вызов `discount/check`; показ «−N%»
  из `config/discounts`; шаг входа перед «Купить»; карточка пробных 20 ч (скрыть после покупки).
- **Панель владельца:** простой UI над `/v1/admin/discount` (создать/отозвать), чтобы не через curl.
- **Server-in-a-Box:** сам провижининг узлов/коробки — отдельная задача (см. роадмап); выпуск
  скидок с неё уже возможен через админ-эндпоинт.
