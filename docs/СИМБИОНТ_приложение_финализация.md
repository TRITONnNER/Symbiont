Этот документ закрывает крупные вопросы, которые нельзя доделать «вслепую» в этой среде

## 1. Каноническая копия приложения — `app/`

В репозитории три копии одного приложения:

| Копия | Что это | Вердикт |
|---|---|---|
| `app/Симбионт.dc.html` | новейший редактируемый исходник из Claude Design (+ `app-config.js`/`app-api.js`) | **✅ КАНОН** — самый полный (337 КБ), чистая разделённость данные/API, подключён к бэкенду и покрыт тестом |
| `webapp/Симбионт.dc.html` | то, что сейчас рендерит Flutter-шелл (через `symbiont-bridge.js`) | 🔁 заменить на `app/`: обновить `WEBSHELL`/`sync_webapp.py`, чтобы шелл брал `app/` + `app-api.js` |
| `site/Симбионт.dc.html` | превью приложения внутри сайта | оставить как превью или убрать |

**Решение:** канон — `app/`. Все правки приложения вносим сюда. Перед сборкой Flutter —
переключить вебшелл на `app/` (одна правка пути в `web_shell_page.dart`/`sync_webapp.py`).

**Сделано в `app/` (проверено):** тарифы `premium/ultimate` (были `standard/pro` → покупка
давала 422), цены/баланс/рефералы из бэкенда через адаптер, авторизация (login-gate), импорт
моста, промокоды, фиче-флаги; убраны фейковые серверы; флаги стран; реф-награда во времени;
пробный **20 ч** учтён. `app/selftest_connector.js` — **12/12**.

## 2. Сканер приложений и сервисов (раздельное туннелирование)

Цель: показать установленные приложения и сервисы на устройстве, чтобы для каждого выбрать
путь каскада (прямой / обход / VPN / реле). Это **нативная** задача (JS/вебшелл сам список
приложений получить не может) — реализуется за контрактом `SymbiontEngine.scanApps()`
(в `singbox_engine.dart` метод уже есть, возвращает `[]` — нужен натив).

**Как получить список — по платформам:**

| ОС | Источник списка приложений | Маршрутизация по приложению |
|---|---|---|
| **Windows** | реестр `Uninstall` + запущенные процессы (имя `.exe`); иконки из ресурсов exe | движок матчит по имени процесса/PID (WinDivert/sing-box) — уже так задумано |
| **Android** | `PackageManager.getInstalledApplications()` → {label, packageName, icon} | `VpnService` умеет per-app allow/disallow по packageName |
| **macOS** | `/Applications` + `NSWorkspace` (запущенные) | сложнее — сопоставление по пути процесса в NE |
| **Linux** | `/usr/share/applications/*.desktop` + процессы | по имени процесса |
| **iOS** | ❌ песочница — список чужих приложений получить нельзя | per-app невозможен → только по **сервисам/доменам** |

**Сервисы (домены) — кросс-платформенно и приватно:**
- Курируемый каталог сервисов (YouTube, Telegram, Steam, банки…) с доменами — в приложении уже
  есть массив `SERVICES`. Пользователь маршрутизирует сервис, не зная доменов.
- «Что реально используется» можно подсказывать по SNI/DNS **локально** (видим только имена, не
  содержимое — как и обещано), без отправки на сервер.

**Сделано (Windows, Dart):** `desktop_engine_io.dart → scanApps()` уже читает реестр
`Uninstall` + теперь **запущенные процессы** (`tasklist`, с фильтром системного шума) —
ловит и portable-приложения, и игры. Возвращает `List<InstalledApp>{name, exe, path}`.

**Осталась сквозная проводка (нужен натив-канал + рендер, не проверить здесь):**
1. **Контракт `SYM_ENGINE`** (в `ENGINE_CONTRACT.md`) расширить методом
   `scanApps(): Promise<[{id,name,exe,kind}]>` — сейчас в контракте только connect/disconnect/onEvent.
2. **flutter-host мост** (`sym_engine_channel.dart`) — форвардить `scanApps` в Dart-движок.
3. **UI приложения**: оверлей скана (сейчас демо-список `DEVICE_APPS`) → звать
   `SYM_ENGINE.scanApps()` (live) с откатом на демо.
4. Выбор пути на приложение → `RoutingRule(kind: processId, match: exe, action)` → `applyRules`
   → `route.rules` sing-box (по `process_name`) — генератор уже умеет (`singbox_config.dart`).
5. **Android**: `scanApps()` через Kotlin `PackageManager` (MethodChannel). **iOS**: per-app нельзя
   (песочница) → скрыть, показать маршрутизацию по **сервисам/доменам** (каталог `SERVICES`).

## 3. Флаги стран — СДЕЛАНО (локальный SVG, без CDN)

- **`app/flags.js`**: `SYM_FLAG_SVG(code)` → **локальный SVG data:URI** для любой страны: точные
  простые флаги для распространённых локаций (NL/DE/FR/FI/SE/JP/…), иначе аккуратная плитка с
  ISO-кодом. **Работает на Windows и офлайн.**
- **Убрана внешняя зависимость:** все `flagcdn.com` (внешний CDN — нарушал «ноль CDN», не работал
  офлайн/на Windows) заменены на `SYM_FLAG_SVG` — в компоненте (4) и в `Picker` (1).
- Полный набор: дополнять карту `FLAGS` по мере появления узлов; фолбэк-плитка гарантирует
  «картинку» у КАЖДОЙ страны уже сейчас.

## 4. Адаптив (альбом/книга, телефон/планшет/ПК/ТВ) — стратегия

Приложение — один DC-компонент с инлайновыми стилями; адаптив только через CSS/раскладку.
**Полную верстку под все форматы нельзя проверить без рендера** — нужен `flutter run` /
браузер на каждом размере. Что делать:

- **Точки проверки:** 360×640 (телефон-портрет), 640×360 (ландшафт), 768 (планшет),
  1280+ (ПК), 1920+ (ТВ, крупный шрифт/фокус-навигация).
- **На что смотреть:** фиксированные `px`-ширины и `grid-template-columns` без `minmax()`;
  ядро связи (ConnectionCore) должно масштабироваться; списки узлов/маршрутов — переноситься;
  оверлеи (оплата/импорт/пикеры) — влезать по высоте с прокруткой; шапка/таб-бар — компактиться.
- **ТВ:** нужна фокус-навигация пультом (tabindex/стрелки) — отдельная задача.
- Рекомендация: снять скриншоты на 5 размерах (`flutter run` / `python3 -m http.server` + окно
  браузера), составить список конкретных переполнений и править точечно. Это следующий проход
  «с рендером».
