# Симбионт — полная архитектура сервиса (спецификация v1)

Единый документ: как работает сам VPN (сервера, протоколы, каскад, контрольная
плоскость), система аккаунтов/подписок/грантов, анти-фрод, удержание, разделение
demo/real, модель данных — и **критический разбор «что сейчас не так»**. Ведём и правим.

---

## 0. Принципы (на них держится всё)

1. **Приватность-первая, «чего нет — то не утечёт».** Сервер хранит минимум: хеши, а не данные. Алиасы (ник/почта/телефон) не верифицируются и могут быть выдуманными — они для опознания только внутри нас.
2. **Адаптивность, а не тумблер.** Продукт — организм связности: каскад прямой → обход → туннель → реле, который сам измеряет сеть и подстраивается. Это сигнатура.
3. **Серверы — только наши.** Server-in-a-Box поднимаем мы (владельцы/сотрудники). Пользовательского self-host пока нет.
4. **Анти-фрод экономикой, а не запретом.** Регистрация свободна; пустой аккаунт бесполезен; барьеры — PoW, rate-limit, репутация.
5. **demo ≠ prod.** Везде явный флаг окружения и признак «реальности» объекта (узел/аккаунт/платёж), чтобы не спутать прототип и боевое.

## 1. Как работает сам VPN (ядро продукта)

### 1.1 Серверный флот (Server-in-a-Box)

**Что это.** Наши VPS, каждый разворачивается скриптом `bootstrap_vps.sh` в готовый узел: ставит sing-box, генерирует конфиг (`gen_server.py`), поднимает сервис (`install.sh`), регистрируется в контрольной плоскости.

**Роли узлов** (поле `role`):
- `entry` — точка входа (то, к чему подключается клиент);
- `relay` — промежуточный для цепочки (detour), скрыт от UI, используется при «занавесе»;
- `exit` — выходной (где трафик выходит в интернет);
- `boost` — игровой PoP (низкий пинг).

**Регистрация узла (само-регистрация).** Узел при старте шлёт `POST /v1/node/register` с HMAC-SHA256-подписью по секрету узла. Сервер проверяет подпись, добавляет узел в реестр (`keys_registry.json`), включает в манифест.

**Манифест** (`manifest.py`) — подписанный список узлов, который тянет клиент:
- подпись (клиент проверяет доверенным публичным ключом `kTrustedPubKey`);
- **монотонная версия** — защита от отката (anti-rollback): клиент не примет манифест старее текущего;
- `relays` парсятся отдельно и скрыты от UI;
- **легальный предохранитель**: сервер отказывается публиковать публичный выход внутри РФ (роль `exit` с РФ-гео не отдаётся в публичный манифест).

**Канареечный раскат** (canary) — новый манифест/узел сначала получают N% клиентов (бакетирование по токену через FNV-1a), потом все. Если ломается — откат до того, как заметит большинство.

### 1.2 Протоколы и каскад (сигнатура продукта)

Каскад из 4 слоёв, клиент идёт сверху вниз, пока не получит связь:

| Слой | Что делает | Технология (у нас) |
|---|---|---|
| **Прямой** | проверка, доходит ли напрямую | обычный сокет + измерение |
| **Обход DPI** | разбивает/маскирует пакеты, чтобы ТСПУ не распознал | winws/zapret (десктоп), fragment/split |
| **Туннель** | полноценный шифр-туннель | sing-box: VLESS-**Reality** / **Hysteria2** / **Shadowsocks-2022** |
| **Реле** | цепочка через промежуточный узел, когда вход «занавешен» | sing-box detour (entry→relay→exit) |

**Выбор протокола туннеля** (`singbox_config.dart`, поле `protocol`): `auto` подбирает по сети; `reality` маскируется под TLS к реальному сайту (лучше против DPI); `hysteria2` — быстрый UDP (хорош при потерях); `ss2022` — простой и быстрый. `xrayCore`-флаг — для узлов, где нужен Xray вместо sing-box.

**Конфиг строится на клиенте** (`SingboxConfig.build`): `endpoint` (вход), `cascade` (цепочка), `relay` (detour), `rules` (per-app/per-site маршрутизация), `protection`, `inbound`, Clash-API (для статистики трафика). На десктопе исполняет `DesktopEngine` (реальный sing-box процессом + winws для обхода); на мобайле — пока stub.

### 1.3 Детект «занавеса» (16 КБ) и адаптация

ТСПУ часто рвёт соединение после ~16 КБ переданных данных (первый пакет проходит, дальше «занавес»). Клиент (`curtain.dart`, `classifyCurtain`) измеряет и классифицирует: `clear / curtain / blocked / slow / partial`. По итогам диагностики (`detectCurtain`) при `curtain/blocked` **автоматически уходит на реле** и сообщает спокойным баннером. Это адаптация, которой нет у обычных VPN.

### 1.4 Выбор узла и измерение

Клиент измеряет пинг/потери по узлам, показывает нагрузку (цвет+иконка+%), выбирает быстрейший доступный нужной роли. Boost-узлы — отдельно для игр (мин. пинг).

### 1.5 Контрольная плоскость (control-plane)

`server.py`: роли (admin/node/client), легальный предохранитель, канареечный раскат, монотонные версии манифеста (anti-rollback), персистентность (`persist.py`, атомарные jload/jsave — `accounts.json`, `threads.json`, `keys_registry.json` переживают рестарт).

### 1.6 Модель безопасности / приватность

- **No-logs трафика**: сервер не пишет, кто куда ходил.
- Сервер знает: факт аккаунта (по хешам), остаток подписки, список устройств (отзываемый). Не знает: реальные почты/телефоны (их нет — только хеши), характер трафика.
- Клиент хранит локальный токен/состояние **зашифрованно** (AES-256-GCM, см. 2.4).

## 2. Идентичность и аккаунты

### 2.1 Крипто-личность

Истинный идентификатор аккаунта — **256-битный секрет** (32 случайных байта, как номер Mullvad, но с полной энтропией). Всё остальное (алиасы) лишь ведёт на него. Из секрета выводится `account_id` (хеш) — он и фигурирует в данных.

> Важно по терминологии: AES-256 — это **шифрование** (для хранилища, п. 2.4), а **опознание** строим на HMAC-SHA256 и хешах. Пароль — Argon2id. Каждый примитив на своём месте.

### 2.2 Алиасы и уникальность

Пользователь регистрирует **любой** алиас: ник, «почту» (хоть выдуманную), «телефон» (хоть `+1`). Тип (`nick/email/phone/free`) — метка для UI, без верификации.

**Уникальность («не два одинаковых»):**
1. **Нормализация** перед сравнением: trim, lower-case; для `phone` — оставить только цифры и `+` (чтобы `+1`, `+ 1`, `1` считались одним).
2. **Хранить `HMAC-SHA256(нормализованный_алиас, серверный_секрет)`** — не сам алиас. Уникальность проверяется по хешу; из дампа БД список алиасов не достать.
3. Один аккаунт может иметь **несколько алиасов** (ник + «почта» + «телефон»), каждый глобально уникален; войти — любым.

> Занятые короткие/красивые алиасы становятся ограниченным ресурсом — это дополнительный анти-фрод-барьер.

### 2.3 Секрет: восстановление и пароль

**Решение по умолчанию (можно поменять):** при регистрации генерим **recovery-код** (производный от 256-бит секрета, показываем один раз — «сохрани это»). Пароль — **опциональный** (кто хочет привычный вход). Пароль хешируется **Argon2id** (медленный KDF), не хранится в открытом виде.

Честная коммуникация: «мы не верифицируем почту/телефон, поэтому восстановить можно только этим кодом/паролем — никто, включая нас, не восстановит иначе». Это и есть приватность.

### 2.4 Шифрование локального хранилища

AES-256-GCM шифрует на устройстве: карту `alias→account`, локальный токен сессии, список устройств. Ключ — из секрета аккаунта/устройства. Украденный файл/база на устройстве нечитаемы.

### 2.5 Минимизация на сервере

| Хранит сервер | НЕ хранит сервер |
|---|---|
| `account_id` (хеш секрета) | сам секрет |
| HMAC-хеши алиасов | сами алиасы (почты/телефоны) |
| Argon2-хеш пароля (если задан) | пароль |
| остаток подписки, гранты, источник | трафик / куда ходил |
| список устройств (id, имя, платформа, last seen) | реальную геолокацию |

## 3. Анти-фрод (без верификации)

1. **Proof-of-Work при регистрации** (mCaptcha-подобный, SHA-256, адаптивная сложность; новым аккаунтам — выше). Незаметно человеку, дорого для фермы.
2. **Rate-limit по /24-подсети** (IP из одной /24 считаем как один источник).
3. **Free работает сразу — «неактивированных» аккаунтов НЕТ.** Аккаунт со старта получает Free и подключается. Барьер не на использование, а на **фарм наград**: свежий аккаунт не может сразу грести реферальные/комбо-бонусы (см. систему репутации 3.1).
4. **Инвайт-граф**: приглашения — дерево доверия; фрод-ветка откатывается целиком.
5. **Дефицит алиасов**: уникальность коротких алиасов мешает массовому однотипному созданию.

### 3.1 Система репутации (видна пользователю в сервисе)

Репутация **не ограничивает VPN** (Free работает сразу). Она метит только **выплату наград**, чтобы фермы не плодили бонусы — при этом **приглашать можно сколько угодно** (это реклама, мы её поощряем). Хитрость: **безлимитны приглашения, метятся только выплаты** за реальные конверсии.

В сервисе показываем экран «Репутация»: текущий уровень, прогресс до следующего, что поднимает, и текущие лимиты выплат.

| Уровень | Как достигается | Лимит выплачиваемых рефералов | Множитель награды | Доп. |
|---|---|---|---|---|
| **Новичок** | свежий аккаунт | до 5 оплачиваемых конверсий/мес | ×1.0 | базовый |
| **Проверенный** | 1-я оплата ИЛИ 14 дней + активность | до 20/мес | ×1.0 | быстрее добавлять устройства |
| **Опытный** | 90 дней + ≥3 реальных реферала | до 100/мес | ×1.25 | ранний доступ к фичам |
| **Амбассадор** | ≥20 платящих рефералов, без фрода | практически без лимита | ×1.5 | спец-бейдж, кандидат на грант |

Принцип: **инвайт-ссылку раздавай хоть миллиону** (реклама не ограничена) — вознаграждение начисляется за **реальные** регистрации/оплаты до лимита уровня. Фейки не платят и режутся PoW + /24 + инвайт-графом, поэтому фарм бесполезен, а честное продвижение — поощряется и растит уровень.

> **«Поддержать проект»** — не отдельный тариф, а **тумблер цены** поверх любого платного: та же функциональность, добровольно дороже, в обмен — бейдж благодарности.

**Игровой буст одинаков на Premium и Ultimate** (полнофункциональный на обоих). Что делает: определяет игру по процессу/портам → пускает **только игровой трафик** через ближайший boost-PoP (split-routing, остальное напрямую) → протокол **Hysteria2 (UDP)** (держит трафик при потерях/джиттере) → при «рваном» маршруте заворачивает через реле для стабильности → показывает **дельту пинга** (было/стало).

### 4.2 Длительности и модели оплаты

- **Период (подписка)** — помесячно / годовой (со скидкой). Для тех, кто всегда онлайн. По умолчанию для платных.
- **Баланс активного времени** — покупаешь N активных часов; **списывается ТОЛЬКО пока туннель активен**, в простое 0. Для тех, кто включает изредка; идеально под крипту.

**Как считается баланс честно и приватно:** длительность сессии меряет **узел** (он и так знает, сколько ты подключён, но НЕ знает содержимое трафика), а не клиент (клиент мог бы занижать). Узел шлёт серверу «аккаунт X активен N минут» → сервер списывает с баланса. Накрутить нельзя, приватность цела (длительность ≠ содержимое).

### 4.3 Подписка как право

`subscription = { tier, mode: period|balance, days_left | active_minutes_left, auto_renew, source }`. Источник: `key/card/crypto/invite/grant`. Пополняется любым способом.

### 4.4 Гранты (премиум по решению владельцев)

Флаг `granted_tier`: `{ tier, expires (дата или «пожизненно»), source, reason }`. Не покупается массово. Выдаётся:
- **с аккаунта владельца/сотрудника** в сервисе (есть роли + админ-токен);
- **через наш Server-in-a-Box** (наша инфраструктура, не пользовательская);
- **спецключом** — одноразовый **подписанный** ключ, в котором зашит `tier+срок` (нельзя подделать/размножить);
- **конкурсы/розыгрыши** — ограниченная партия грант-ключей; приз — внутреннее время/доступ, **не выводимый в деньги** (юридически безопасный формат для РФ).

Риск обычного lifetime снят: это не выручка, а PR/награда под нашим контролем по количеству.

### 4.5 Оплата

Абстракция `PaymentProvider` (подключать что угодно). Под РФ: **СБП, карты «Мир», ЮKassa/ЮMoney, крипта (USDT/BTC/Monero)**. Не зависеть от Visa/Mastercard. В `dev` — **sandbox-провайдер** (фейковая оплата). Крипта-канал особенно ценен приватной аудитории.

| Регион | Способы оплаты |
|---|---|
| **РФ** | СБП · карты «Мир» (ЮKassa) · ЮMoney · крипта |
| **Международно** | крипта (USDT/BTC/XMR) приоритетно · зарубежные карты — позже |
| **Везде** | крипта = −10% к цене |

### 4.6 Серверная экономика (ВСЕ числа — в сервисе, не зашиты в приложение)

Цены, фичи тарифов, награды рефералов, пороги репутации, бонусы — отдаём с бэкенда эндпоинтом `GET /v1/config/economy`, а приложение **рендерит из него**. Зачем:
- **Видно пользователю**: экраны тарифов/репутации/рефералов показывают актуальные правила и числа (как ты и просил — «прописывать в самом сервисе»).
- **Меняется без обновления приложения**: подкрутили цену/награду на сервере — у всех обновилось.
- **A/B и регионализация**: разные цены/правила по региону из одного источника.

`economy.json` (пример полей): `tiers[]` (фичи), `prices{регион→тариф→длительность}`, `referral{рег, премиум_мес, премиум_год, …}`, `reputation{уровни, пороги, лимиты, множители}`, `combo{пороги, бонусы}`, `payments{регион→методы}`.

## 5. Устройства

- Аккаунт → **список устройств**: id, имя, платформа, последняя активность, статус.
- **Роль `owner-class`** (усиленные права), таких может быть несколько. Может: **отзывать** другие устройства и **повышать** обычное устройство до `owner-class` (тогда то тоже может управлять списком/повышать). Отозванное теряет доступ при следующей проверке токена.
- Первое устройство — `owner-class` по умолчанию.
- **Устройства без лимита на Premium/Ultimate**; Free — 1–2. Число устройств — фича уровня, **не множитель цены**.
- *На будущее (безопасность):* «супер-владелец» = держатель секрета аккаунта, которого нельзя отозвать другим owner-class (страховка от перехвата повышенным устройством).

### 6.1 Рефералы (двусторонняя награда, усиливается при покупке)

| Что сделал приглашённый | Инвайтеру | Приглашённому |
|---|---|---|
| Зарегистрировался + активировал Free | +3 дня | +3 дня |
| Купил Premium-месяц | +30 дней | +10 дней |
| Купил Premium-год | +90 дней | +30 дней |
| Купил Ultimate | +120 дней | +40 дней |

Награда за покупку — только если оплата реальная (не возврат). Выплаты режутся лимитом уровня репутации (3.1) и инвайт-графом при фроде. **Приглашать можно неограниченно** — метятся только выплаты.

### 6.2 Лояльность / комбо

- **Комбо-подписка**: считаем «накопленные оплаченные месяцы». Помесячно 3 раза подряд → бонус на 3-м. **Купил год сразу** → счётчик += 12, бонусы срабатывают на порогах **3 / 6 / 12 мес** (булк-покупатель не в проигрыше vs помесячный).
- **Кешбэк-лояльность**: бонусные дни за продление/долгую подписку — по факту оплаты, **не по аптайму** (приватно, без фарма ботами).

### 6.3 Геймификация (осторожно)

- **«Колесо фортуны» — детерминированная награда за продление** (без случайности при платном входе, без вывода в деньги) → рекламная механика, не лотерея (безопасно по 138-ФЗ/244-ФЗ/38-ФЗ). Случайность — только для бесплатного ежедневного бонуса.
- **Streak «дней под защитой»** — мягко, опционально, **без публичных лидербордов и наказующих пушей**.

## 9. Что сейчас НЕ ТАК и что чинить (критический разбор текущего кода)

| Проблема | Сейчас | Чинить |
|---|---|---|
| **Секреты захардкожены** | `demo-admin-token`, `demo-node-secret` в коде | вынести в env/секрет-хранилище; для prod — сгенерированные, не дефолтные |
| **Инвайт-код — плейсхолдер** | `СИМБ-7K2Q` зашит | генерировать из инвайт-системы, привязать к графу |
| **Нет крипто-личности/алиасов** | вход по токену, без алиас-уникальности | внедрить 256-бит секрет + HMAC-алиасы + нормализацию |
| **Нет анти-фрода** | регистрация ничем не защищена | добавить PoW + rate-limit /24 + репутацию |
| **Нет устройств** | нет списка/отзыва | добавить device-реестр + owner-class + revoke |
| **Тарифы примитивные** | free/trial/pro «галочкой» | внедрить таблицу возможностей + баланс-дни + гранты |

| **Mock vs real движок** | на мобайле туннель — stub | довести мобильный sing-box; пометить demo/real |

| **Нет env-разделения** | demo и prod не разделены явно | флаг `env` + `synthetic/sandbox` на объектах |
| **Пароль без KDF** (если будет) | — | Argon2id обязательно |

## 10. Поэтапный план

**Этап 1 (фундамент аккаунтов):** крипто-личность + алиасы (HMAC/нормализация) + recovery-код/опц.пароль (Argon2) + AES-хранилище + env-разделение + вынос секретов из кода.
**Этап 2 (анти-фрод + устройства):** PoW при регистрации, rate-limit /24, реестр устройств + owner-class + revoke.
**Этап 3 (тарифы + оплата):** таблица тарифов, баланс-дни, `PaymentProvider` (sandbox + крипта/СБП), гранты (admin/спецключ).
**Этап 4 (удержание):** рефералы + инвайт-граф, кешбэк-лояльность, колесо-как-награда, мягкий streak.
**Этап 5 (доводка VPN):** мобильный sing-box, пер-узловые секреты, метрики нагрузки, премиум-локации/выделенный IP.

## 11. Решения по умолчанию (можно менять)

- Секрет: **recovery-код по умолчанию**, пароль опционален.
- Тарифы: общепринятые **Free / Premium / Ultimate** + «**Поддержать**» как тумблер.
- Устройства: **без лимита на Premium/Ultimate**; Free — 1–2. Owner-class может повышать другие устройства.
- Оплата: **период** (по умолчанию) + **баланс активного времени** (списывается только под подключением, мерит узел).
- Репутация: видна в сервисе; приглашать неограниченно, метятся только выплаты по уровням.
- Экономика (цены/награды/пороги): **серверная** (`/v1/config/economy`), показывается в приложении.
- Семейные тарифы: **отложены**.
- Self-host Server-in-a-Box: **убран** (только наша инфраструктура).
- Гранты: владелец/сотрудник + наш Server-in-a-Box + спецключ + конкурсы.
