# Симбионт — какой VPS купить под узел и как подключить через Server-in-a-Box

Практический гид: **какие серверы подходят под наши критерии, где и как их купить, и как за
одну команду превратить чистый VPS в живой узел Симбионта.** Данные по провайдерам — на
середину 2026; **цены/локации/условия проверяйте на сайте провайдера при покупке** (меняются),
а вот критерии ниже — стабильные, они заданы нашим кодом и скриптами.

---

## 1. Наши критерии (что реально требует узел)

Взято из `docs/СИМБИОНТ_server_in_a_box.md`, `symbiont_build/server/README.md`,
`docs/RUNBOOK_MVP.md` и логики `bootstrap_vps.sh` / `gen_server.py` / бэкенда.

| Критерий | Требование | Почему |
|---|---|---|
| **ОС** | Ubuntu **22.04 или 24.04**, чистая | `install.sh`/`bootstrap_vps.sh` рассчитаны на неё |
| **Доступ** | **root по SSH** (пароль или ключ) | ставим sing-box, systemd, firewall |
| **Ресурсы** | от **1 vCPU / 1 ГБ RAM** на старт | десятки пользователей на одном VPS; для нагрузки — больше |
| **Архитектура** | **amd64** или **arm64** | `install.sh` качает нужный бинарь sing-box сам |
| **IP** | **публичный статический IPv4** | Reality работает по IP, домен НЕ нужен |
| **Локация** | **ВНЕ России** для точки выхода (edge) | бэкенд запрещает публичный exit в РФ (`code==RU` → только `relay`); для аудитории РФ лучше NL/FI/DE и рядом |
| **Порты** | открыть **443/tcp, 8443/UDP, 9443/tcp** (+ `8000/tcp`, если рядом бэкенд) | Reality (TCP 443) · Hysteria2 (**UDP** 8443) · SS-2022 (TCP 9443) |
| **UDP** | **разрешён исходящий/входящий UDP** | без него Hysteria2 не поднимется (autotune сам его отключит, но потеряете скорость/игры) |
| **Трафик** | **безлимит или большой лимит** (VPN «ест» много) | autotune замеряет ёмкость и ставит стартовую загрузку |
| **ToS** | провайдер **разрешает VPN/прокси** | бюджетные хосты часто запрещают → блок аккаунта; это критично |
| **«Чистый» IP** | свежий IP, желательно НЕ из диапазонов, уже заблокированных РКН | иначе часть пользователей из РФ не достучится (каскад повышает шансы, но не гарантирует) |
| **Оплата** | любой доступный способ. **Крипта (USDT/BTC/XMR) снимает привязку к РФ-платежам** и открывает весь международный рынок; альтернативы — МИР/СБП/ЮMoney или карта/PayPal | не зацикливайтесь на «оплата из РФ» — если есть крипта, берите лучший узел по гео/цене/ToS |

> Мини-чеклист при выборе: **Ubuntu 22/24 · root · ≥1 vCPU/1 ГБ · публичный IPv4 · локация вне РФ ·
> UDP разрешён · большой/безлимит трафик · ToS разрешает VPN · способ оплаты вам доступен (крипта — самый универсальный).**

## 3. Как купить (чтобы сразу подошло под нас)

1. **Локация**: выберите точку **вне РФ**, близкую к аудитории — Нидерланды, Финляндия, Германия
   (для РФ обычно лучшая задержка/пиринг). Для нескольких стран в списке серверов — берите VPS в
   разных локациях.
2. **Образ ОС**: **Ubuntu 22.04** или **24.04** (64-бит). Не «minimal», обычный server-образ.
3. **Тариф**: **1 vCPU / 1–2 ГБ RAM**, NVMe/SSD, **большой или безлимитный трафик**. Масштабируетесь
   позже (наш `rollout`/heartbeat это переживут).
4. **Сеть**: включите **публичный IPv4**. Домен не нужен (Reality работает по IP).
5. **Доступ**: **root по SSH** — ключ надёжнее пароля (`ssh-keygen`, вставьте публичный ключ при
   создании).
6. **Firewall провайдера**: если у хостера свой firewall в панели (Vultr/OVH/Hetzner/…), **откройте
   заранее**: `443/tcp`, `8443/udp`, `9443/tcp`, и `8000/tcp` (если на этом же VPS бэкенд).
   **UDP 8443 — обязательно**, иначе Hysteria2 не заработает.
7. **ToS/оплата**: убедитесь, что VPN/прокси разрешён; выберите доступный способ оплаты
   (МИР/СБП/ЮMoney/крипта — см. таблицу).

## 4. Подключение через Server-in-a-Box — одна команда

Полный разбор: `docs/СИМБИОНТ_server_in_a_box.md`, `symbiont_build/server/README.md`,
`docs/RUNBOOK_MVP.md`. Кратко — два шага.

### Шаг 0 (один раз): бэкенд
Если у вас ещё нет задеплоенного бэкенда — поднимите его одной командой на любом из этих же VPS
(он же может нести и узел):

```bash
# на чистом Ubuntu-VPS, от root — ставит FastAPI-бэкенд + nginx + systemd,
# печатает ADMIN_TOKEN и NODE_SECRET (сохраните их!)
curl -fsSL https://raw.githubusercontent.com/TRITONnNER/Symbiont/main/symbiont_build/server/deploy-backend.sh | sudo bash
```

Из вывода запомните **`SYMBIONT_NODE_SECRET`** (им узлы подписывают саморегистрацию) и
**`ADMIN_TOKEN`** (вход в панель).

### Шаг 1: превратить VPS в узел
На **каждом** купленном VPS (чистый Ubuntu 22.04/24.04, от root):

```bash
curl -fsSL https://raw.githubusercontent.com/TRITONnNER/Symbiont/main/symbiont_build/server/get.sh \
  | sudo bash -s -- --register-to https://ВАШ_БЭКЕНД --node-secret СЕКРЕТ_ОПЕРАТОРА
```

- `--register-to` — адрес вашего бэкенда из Шага 0.
- `--node-secret` — тот самый `SYMBIONT_NODE_SECRET`.
- Необязательно: `--code NL --country Netherlands --sni www.microsoft.com` — иначе страна/SNI
  **подберутся сами** по IP (`node_autotune`).

**Что происходит само** (`bootstrap_vps.sh`):
1. Ставит зависимости и набор узла в `/opt/symbiont`.
2. Авто-подбор страны и живого **SNI** для Reality-маскировки; ставит **sing-box**
   (VLESS-Reality `443/tcp` + Hysteria2 `8443/udp` + Shadowsocks-2022 `9443/tcp`), systemd,
   открывает порты в `ufw`.
3. **Само-регистрация** в подписанном манифесте бэкенда (`POST /v1/node/register`, HMAC) → бэкенд
   пересобирает и переподписывает манифест → **узел появляется у клиентов сам**.
4. **Heartbeat каждые 60 с**: замолчал дольше `NODE_STALE_SEC` → само-починка убирает из списка;
   вернулся — снова появляется. Живая загрузка тоже идёт в манифест.
5. Ставит CLI **`symbiont-node`**.

> Если у провайдера firewall в панели — ещё раз проверьте, что **443/tcp, 8443/udp, 9443/tcp**
> открыты и там (ufw открывает только на самом сервере).

### Шаг 2: проверка и управление на сервере — `symbiont-node`

```
symbiont-node status      состояние узла + heartbeat (id, страна, протоколы)
symbiont-node logs 100 -f логи sing-box (следить)
symbiont-node restart     перезапуск
symbiont-node update      обновить до свежей версии
symbiont-node remove      снять узел (уйдёт из списка по self-heal)
symbiont-node info        полный манифест узла
```

Параметры оператора хранятся в `/etc/symbiont/sib.env`.

### Шаг 3: панель оператора
Скачайте **`symbiont_build/server/sib-console.html`** (один файл, без CDN) и откройте в любом
браузере. Вход по `ADMIN_TOKEN` (владелец) или staff-токену (работник). Вкладка **«Серверы»** —
увидите свой узел онлайн, сможете снять его или выкатывать манифест волной (canary %).

## 5. Ручной путь (без Server-in-a-Box), для справки

Если хотите собрать конфиг заранее у себя и залить на сервер (`symbiont_build/server/README.md`):

```bash
# 1) на своей машине — сгенерировать конфиг узла и запись для манифеста
python3 symbiont_build/server/gen_server.py --host <IP_сервера> --code NL --country Netherlands \
    --sni www.microsoft.com --out ./out

# 2) скопировать папку server/ на VPS и поставить
scp -r symbiont_build/server root@<IP>:/root/ && ssh root@<IP> 'cd server && sudo bash install.sh'

# 3) добавить запись из out/manifest_node.json в манифест бэкенда (или publish_nodes.py)
```

`install.sh` идемпотентен: ставит sing-box, генерит серт для Hysteria2, поднимает systemd,
открывает порты в ufw, валидирует конфиг (`sing-box check`).

## 6. Несколько серверов и масштаб

- **Добавить ещё узел**: повторите Шаг 1 на новом VPS с тем же `--register-to`/`--node-secret` —
  он сам появится в списке. Разные страны — разные локации VPS.
- **Балансировка/география**: клиент строит каскад Reality → Hysteria2 → SS-2022 и выбирает узел
  по пингу; мёртвые узлы уходят по heartbeat.
- **Нагрузка**: один VPS тянет десятки пользователей; для коммерции — несколько узлов в разных
  точках и апгрейд тарифа.

---

## 7. Юридическая заметка

- Узел (как любой VPN) **видит трафик пользователя на входе** в туннель — держите сервера в
  юрисдикции, которой доверяете, и не логируйте лишнего.
- **В России обход блокировок ресурсов из реестра запрещённых — незаконен.** Соблюдайте
  законодательство страны, где находитесь и где размещаете сервера, и условия использования (ToS)
  провайдера.
