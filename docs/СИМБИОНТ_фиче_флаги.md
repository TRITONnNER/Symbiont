# Симбионт — фиче-флаги: включать/выключать блоки на сайте и в приложении

Механизм, чтобы **легко гасить и включать** блоки, платформы и доп-информацию —
одним местом сразу для сайта и приложения. Пример из задачи: macOS-сборка не готова →
выключаем `download.macos` → карточка macOS исчезает и на сайте, и в приложении, без пересборки.

Ложится на паттерн, который в проекте уже есть: бэкенд отдаёт `/v1/config/economy`, а
оболочка кэширует ответ и рендерит из него. Флаги — ровно то же самое, отдельным манифестом.

---

## 1. Как это устроено (одна картинка)

```
DEFAULT_FLAGS (server.py)  ──►  GET /v1/config/flags  ──►  кэш на клиенте  ──►  гейтинг блока
        ▲                              ▲                         │
   flags.json (override,         (fail-open: нет бэкенда/          ├─ Сайт/оболочка:  SYM_FLAG('download.macos')
    без пересборки)               опечатки → блок ВКЛючён)         └─ Приложение:    flags['download']['macos']
```

- **Единый источник** — `DEFAULT_FLAGS` в `symbiont_build/backend/server.py`.
- **Override без пересборки** — файл `flags.json` рядом с бэкендом (как `economy.json`);
  меняете значение → эффект сразу, деплой не нужен. `flags.json` в `.gitignore` (серверная конфигурация).
- **Обе поверхности читают ОДИН манифест** → один флаг гасит блок и на сайте, и в приложении.
- **Fail-open:** если бэкенд недоступен или флага нет — блок считается **включённым**
  (лучше лишний блок, чем пустая витрина в демо/оффлайн-режиме). Явный `false` прячет.

## 3. Схема флагов (что можно гейтить сейчас)

```jsonc
{
  "version": 1,
  "download":    { "ios": true, "android": true, "windows": true,
                   "macos": true, "linux": true, "extension": true },   // платформы «Скачать»
  "coming_soon": { "enabled": true, "apple_tv": true, "android_tv": true,
                   "openwrt": true, "cli": true },                       // блок «Скоро» и пункты
  "site":        { "pricing": true, "download": true, "support": true, "legal": true,
                   "hero_widget": true, "features": true, "numbers": true, "faq": true,
                   "import_bridge": true, "lang_switcher": true },       // крупные секции/страницы
  "legal":       { "canary": false, "law_requests": true,
                   "key_revocations": true, "jurisdictions": true },     // правовые блоки (канарейка ВЫКЛ по умолчанию)
  "pricing":     { "subscriptions": true, "balance": true, "balance_300h": true,
                   "annual_toggle": true, "crypto_discount": true },     // модели цен
  "app":         { "import_bridge": true, "wheel": true, "referrals": true,
                   "network_analysis": true, "traffic_map": true, "key_checker": true }
}
```

Схема легко расширяется — добавили ключ в `DEFAULT_FLAGS`, начали читать на клиенте. Fail-open
означает: старый клиент, не знающий нового флага, просто покажет блок (ничего не сломается).

## 4. Как выключить блок (для оператора)

Создать/отредактировать `flags.json` рядом с бэкендом. Пример из задачи — macOS не готова:

```json
{ "download": { "macos": false } }
```

> Важно: `flags.json` **заменяет** дефолты целиком (как `economy.json`). Чтобы не перечислять
> всё, оператору удобнее отдавать полный объект (склонировать `DEFAULT_FLAGS` и поменять нужное).
> Если хотите «частичный» override (только изменённые ключи поверх дефолтов) — это 3 строки
> в эндпоинте (`{**DEFAULT_FLAGS, **json}` с глубоким слиянием); готов включить, если нужно.

Эффект — сразу на следующем запросе, и на сайте, и в приложении. Пересборка не нужна.

## 5. Как гейтить блок (для фронтенда)

### 5.1. Сайт / оболочка (`Симбионт.dc.html`)
Мост уже кладёт флаги в `window.SYM_DATA.flags` и даёт помощник `SYM_FLAG(path, dflt)`.
Карточки платформ строятся из массива данных — достаточно **отфильтровать** его по флагу:

```js
// было: показываем все платформы
const _dl = [ {id:'ios',…}, {id:'android',…}, {id:'macos',…}, … ];
// стало: скрываем выключенные
const dlPlatforms = _dl.filter(p => SYM_FLAG('download.' + p.id));
```

Для целых секций — обычный `sc-if` вокруг блока:

```html
<sc-if value="{{ flagLegalCanary }}">  …блок канарейки… </sc-if>
```
```js
const flagLegalCanary = SYM_FLAG('legal.canary', false);   // канарейка по умолчанию скрыта
```

### 5.2. Приложение (Flutter)
`ApiClient.flags()` уже есть. Подтянуть один раз при старте (рядом с `economy()`), положить в
`AppState`, и гейтить виджеты:

```dart
final flags = await api.flags();          // в AppState, как economy
bool flag(String path, [bool dflt = true]) { /* обход по точкам, fail-open */ }

if (flag('download.macos')) PlatformCard(macOS)   // или скрыть пункт меню/фичу
if (flag('app.import_bridge')) ImportBridgeButton()
```

## 6. Что осталось довести (тонкий слой)

1. **Гейтинг конкретных блоков в вёрстке** — расставить `SYM_FLAG(...)`/`sc-if` по блокам сайта
   и `flag(...)` по виджетам приложения (плумбинг готов, осталось «повесить» на блоки).
2. **Загрузка флагов в `AppState`** приложения (одна строка рядом с загрузкой economy) + помощник `flag()`.
3. **Панель владельца (опционально)** — админ-эндпоинт `POST /v1/admin/flags` (под `ADMIN_TOKEN`),
   пишет `flags.json`; простой UI с тумблерами. Тогда включать/выключать можно из интерфейса, без правки файла.

## 7. Расширения на будущее (когда понадобится)

- **Раздельно сайт/приложение.** Сейчас манифест общий (это и есть плюс — один тумблер на обе).
  Если нужно разное — добавить ветки `surfaces.site` / `surfaces.app`, читаемые поверх общих.
- **Постепенный раскат (%),** A/B, гейтинг **по региону/языку** (напр. показывать блок только для `ru`) —
  добавляется полем в манифест и одной проверкой в `SYM_FLAG`/`flag`.
- **Баннер-объявление** (техработы, акция) — тот же механизм: `notice: {enabled, text, kind}`.
- **Частичный deep-merge override** (см. §4) — чтобы `flags.json` содержал только изменения.

---

## 8. Почему именно так

- **Ноль пересборок.** Готовность платформы/блока — операционное решение, а не релиз.
- **Одна правда на обе поверхности.** Не рассинхронизируется сайт и приложение.
- **Безопасно по умолчанию.** Fail-open: сбой бэкенда не превращает сайт в пустой каркас;
  а чувствительное (канарейка) явно выключено в дефолтах.
- **Уже проверяемо.** Бэкенд-слой реализован и покрыт тестом здесь; фронту остаётся «повесить» флаги на блоки.
