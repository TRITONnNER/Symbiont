разборы импорта и баланса времени).

- 🟢 **Полировка/решение** — качество или выбор владельца.

**Кто делает:** `[Оператор]` инфраструктура · `[Натив]` платформенная разработка ·

## A. Фундамент — общий для сайта и приложения

### A1. 🔴 Боевые узлы (флот VPS) — `[Оператор]`
Без реального сервера **не работают** VPN, каскад, маршрутизация, game-boost, ad-block,
баланс времени, статус узлов. Это не баг — это отсутствие инфраструктуры (фейковых узлов
в приложении намеренно нет).
- Поднять VPS вне РФ: `server/bootstrap_vps.sh` → `gen_server.py` → `register_node.py` → узел входит в **подписанный манифест**.
- Заполнить реальные секреты узлов (сейчас в конфиге плейсхолдеры `FROM_MANIFEST`: server/uuid/public_key/short_id/sni/пароли).
- **Relay-узлы** — «белые» внутри-РФ IP для detour против whitelist (каскад ступень «реле»).
- Разнести по регионам/юрисдикциям (для карты в «Правовом» и выбора локаций).

### A2. 🔴 Прод-деплой бэкенда — `[Оператор]` + `[Backend]`
Бэкенд (FastAPI) готов и протестирован (**17/17 наборов, ~339 проверок**), но крутится
как процесс с in-memory + JSON-persist.
- Прод-хостинг + домен + TLS (сейчас домен `symbiont.app` выдуман).
- Durable БД: persist-слой есть (JSON и **SQLite** — `selftest_persist_sqlite.py`), для прода включить SQLite/Postgres + **бэкапы** реестра ключей и аккаунтов.
- Секреты в окружении: `SYMBIONT_ADMIN_TOKEN`, ключ подписи манифеста/ключей (Ed25519), webhook-HMAC.
- Мониторинг узлов (heartbeat уже есть) + алерты на выпадение/деградацию.

### A3. 🔴 Платёжный провайдер — `[Backend]` + `[Владелец]`
Монетизации сейчас нет в бою: в проде `purchase` возвращает `pending` без ссылки/QR;
`/v1/subscription/checkout` (описан в `API.md`) не реализован. Sandbox+webhook работают.
- Выбрать провайдера: ЮKassa / CloudPayments / крипто-шлюз.
- `purchase` → вернуть `checkoutUrl`/QR; провайдерский вебхук → существующий `/v1/billing/webhook` (HMAC, идемпотентно уже готов).
- Замапить `product → цена` из экономики на стороне провайдера; серверная сверка суммы.

### A4. 🔴 «Баланс активного времени» — полная реализация — `[Backend]`+`[Натив]`+`[Фронт]`
Модель готова и покрыта тестами, но метеринг не замкнут. Детали — `docs/СИМБИОНТ_баланс_времени_реализация.md`. Кратко три дыры:
- **Метеринг-агент на узле** (никто не зовёт `/v1/node/session`).
- **Enforcement при нуле** (ничто не рвёт туннель на 0 минут).
- **Идемпотентность** (кумулятивное списание + `session_token` из нового `/v1/node/authorize`).
- Плюс: крипто-скидка −10 % в UI, 300 ч в flutter-экране, решение по Ultimate-балансу.

## B. Приложение (десктоп + мобайл)

### B1. 🔴 Нативный мобильный туннель — `[Натив]`
Dart-сторона `SingboxEngine` боевая (MethodChannel/EventChannel), **натив не написан**:
- Android: `VpnService` + встроенный `libbox` (sing-box).
- iOS/macOS: NetworkExtension **Packet Tunnel**.
- Пока мобильные сборки идут на `MockEngine` (движок намеренно не подключён в `main.dart`).
- Когда натив готов — заменить движок в `main.dart` + шаги `NATIVE_INTEGRATION.md`.

### B2. 🟡 Десктопный обход DPI — `[Натив/Оператор]` + прогон на Windows
Написано и сбалансировано, но требует реального прогона (в среде сборки нет Windows/winws):
- winws/zapret (от админа, WinDivert, скрытый запуск) — все приложения + QUIC.
- ByeDPI (без админа, SOCKS5) — только приложения, уважающие системный прокси.
- Автоподбор рабочей стратегии под провайдера (~20 стратегий, жёсткие таймауты).
- Подтвердить на реальных провайдерах (обход DPI сетезависим у всех инструментов).

### B3. 🟡 Собрать и прогнать Flutter-клиент — `[Владелец/Натив]`
- `flutter run/build -d windows` (и macos/linux) — в т.ч. кнопка «Проверить ключ», вход по recovery-коду, PoW-регистрация (Dart-часть готова).
- Тулчейн-нюансы Windows: NuGet для `flutter_inappwebview_windows`; макрос `_SILENCE_EXPERIMENTAL_COROUTINE_DEPRECATION_WARNINGS` на новых MSVC (см. `WEBSHELL.md`).
- WebView2 Runtime на целевых машинах.

### B4. 🟡 Импорт своей конфигурации («свой мост») — `[Фронт]`+`[Backend]`
Сейчас **заглушка**: кнопка «Импортировать» = `closeOverlay`, ссылка не парсится/не хранится.
Реализуемо дёшево (каскад уже принимает доп. outbound). План — `docs/СИМБИОНТ_идея_импорт_своего_моста.md`.
Решить: доделать к запуску или пометить «Скоро».

### B5. 🟢 Мобильные сборки в сторы — `[Натив/Владелец]`
Упаковка/подпись/публикация iOS (App Store) и Android (Google Play + APK); реальные версии/размеры
(в аудите выдуманы: v3.4.1 при реальной `pubspec` 0.1.0).

### B6. 🟢 Глоссарий/FAQ на 51 язык — `[Фронт]`
UI-строки уже на 55 языках (по 391 ключу); глоссарий/FAQ пока ru/en/es/de, остальные —
англ. фоллбэк. Дозаполнить при желании.

## D. Правовое и операционное (для честного запуска) — `[Владелец]`

- **Юрлицо/домен/контакты** для копирайта и связи.
- **Политика/Условия** — сверить формулировки с реальностью (0 логов / RAM-only / «оплата мимо нас» — последнее уточнить после выбора провайдера A3).
- **Варрант-канарейка**: завести реально (Ed25519-инфраструктура у проекта есть — подписывать и обновлять по расписанию) **или убрать** раздел; фейковая подпись хуже отсутствия.
- **Статистика запросов органов / отзыв ключей**: начать с честных значений (реестр знает реальное число отозванных) или пометить демо; не выдумывать журналы.
- **Юрисдикции хостинга** — реальная карта (после A1).

## E. Безопасность и наблюдаемость (для стабильной работы) — `[Backend]`+`[Оператор]`

- **Ротация uTLS-fingerprint** из манифеста: обновлять целевую версию Chrome (устаревший отпечаток сам становится сигнатурой).
- **uTLS ≥ 1.8.2** в сборке узла (CVE-2026-26995/27017).
- **Бэкапы** реестра ключей/аккаунтов; ротация секретов.
- **Anti-abuse** баланса времени (см. A4): `session_token`, sanity-cap, HMAC узла.
- **0 логов / RAM-only** — обеспечить операционно на узлах (в коде заложено).
