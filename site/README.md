# Симбионт — сайт (исходный код)

Исходники сайта-витрины **отдельными файлами** — без минификации и без сборки
в один файл. Правьте `.dc.html` и `.js` напрямую.

---

## Как запустить локально

Страницы подгружают друг друга и данные через `fetch`, поэтому просто открыть
файл через `file://` недостаточно — нужен любой статический сервер:

```bash
# из этой папки
python3 -m http.server 8080
# затем открыть в браузере:
#   http://localhost:8080/Симбионт%20-%20сайт%20-%20Главная.dc.html
```

Точка входа — `Симбионт - сайт - Главная.dc.html`. Остальные страницы связаны
ссылками в шапке/подвале.

```

site-config.js        — ДАННЫЕ по умолчанию (цены/тарифы/платформы/флаги/скидки)
```

> Формат страниц — **Design Components** (`.dc.html`): разметка + класс логики,
> стили инлайновые. Это обычные HTML/JS-файлы, редактируемые вручную; `support.js`
> собирает из них страницу в браузере.

## Данные и подключение вашего API

Все числа и списки вынесены в **`site-config.js`** (`window.SYM_CONFIG`) и служат
фолбэком. **`site-api.js`** (`window.SYM_API`) умеет заменить их ответом сервера.

По умолчанию сайт **ничего не запрашивает** и работает на значениях из
`site-config.js`. Когда бэкенд готов:

```js
SYM_API.base = 'https://api.simbiont.app';         // ваш origin
SYM_API.headers = { Authorization: 'Bearer ' + token }; // при необходимости
SYM_API.bootstrap();   // тянет economy/flags/discounts, вливает в SYM_CONFIG,
                       // рассылает событие 'sym-config' — страницы перерисуются
```

Точечно, без сети, тоже можно:

```js
SYM_CONFIG.merge({ economy: /* ответ /v1/config/economy */ });
window.dispatchEvent(new CustomEvent('sym-config'));
```

Страницы `Цены` и `Скачать` слушают `sym-config` и обновляются на лету.

### Эндпоинты

| Метод | Путь | Отдаёт / принимает |
|---|---|---|
| GET | `/v1/config/economy` | тарифы, цены, продукты, `crypto_discount` |
| GET | `/v1/config/flags` | фиче-флаги (показ блоков/поведение) |
| GET | `/v1/config/discounts` | промокоды, комбо, рефералы |
| GET | `/v1/config/parse-bridge` | конфиг «мост/парсер» |
| POST | `/v1/billing/purchase` | `{ product, method, currency }` → `{ status, checkoutUrl? }` |

Пути можно переопределить: `SYM_API.endpoints.economy = '...'`.

### Что использует какие данные

- **Цены** → `SYM_CONFIG.economy.prices` (цены), `.balance` (пакеты времени),
  `.crypto_discount` / `SYM_CONFIG.discounts.crypto` (−10 % за крипту).
  Кнопка оплаты вызывает `SYM_API.purchase(...)`, если задан `SYM_API.base`
  (иначе — демо-подтверждение). `product` формируется как `premium_month`,
  `ultimate_year`, `balance_100h`, `balance_300h`.
- **Скачать** → `SYM_CONFIG.platforms` (версия/размер/требования/`url` кнопки).

### Формы ответов

Значения по умолчанию в `site-config.js` — это и есть ожидаемая форма ответов
(economy / flags / discounts / parse-bridge). Достаточно вернуть с сервера такой
же JSON. Реальные числа и жизненный цикл оплаты описаны в `PRICING.md`.

## Замечания

- Валюта по региону: `ru → ₽`, иначе `→ $` (см. `economy.currency_by_region`).
- Имена файлов — кириллицей, с пробелами; страницы ссылаются друг на друга по
  этим именам. При переименовании обновите ссылки в `SiteHeader`/`SiteFooter` и
  переходы вида `window.location.href='Симбионт - сайт - Скачать.dc.html'`.
- Шрифты и флаги подключаются извне (Google Fonts, flagcdn.com); локальных
  бинарных ассетов нет.
