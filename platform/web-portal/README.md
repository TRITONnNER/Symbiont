# Симбионт — веб-портал

Оболочка (`webapp/`) как обычный сайт: аккаунт, тарифы, узлы, маршруты,
поддержка — всё в браузере. Отдаём статику и проксируем `/v1` на бэкенд с
**одного origin**, поэтому `SYM_CONFIG` не нужен (мост по умолчанию ходит на тот
же origin, `live:true`), и CORS не участвует.

VPN-движок в браузере не работает — на портале «Подключиться» проигрывает
демо-каскад. Реальное подключение — в приложении (`flutter-host/`) или через
расширение-компаньон. Портал закрывает всё остальное (регистрация, оплата,
управление устройствами, правила, поддержка).

## Прод (Docker + nginx)

```bash
# из КОРНЯ репозитория:
docker build -f platform/web-portal/Dockerfile -t symbiont-portal .
docker run -p 8080:80 symbiont-portal
# бэкенд поднимите на 127.0.0.1:8600 (или поправьте upstream в nginx.conf)
```

## Локально (dev, без nginx)

```bash
# бэкенд:
cd symbiont_build/backend && python run_local.py
# портал (статика + прокси /v1):
python platform/web-portal/serve_portal.py 8080 http://127.0.0.1:8600
# открыть http://127.0.0.1:8080/
```

Проверено: при загрузке БЕЗ какого-либо `SYM_CONFIG` портал сам уходит в живой
режим (`apiBase:''`, узлы приходят из проксированного `/v1/manifest`).

## Файлы

| Файл | Роль |
|------|------|
| `nginx.conf` | статика оболочки + reverse-proxy `/v1` → бэкенд (один origin) |
| `Dockerfile` | образ nginx с вшитой `webapp/` |
| `serve_portal.py` | то же самое для локальной разработки на чистом Python |
