# Симбионт — веб-клиент (продуктовый UI)

Это **ваш дизайн из Claude Design**, сделанный автономным (offline) веб-приложением:
Design-Components-оболочка + рантайм (`support.js`), с локально вшитыми React/Babel,
шрифтами (Golos Text, JetBrains Mono, Noto Sans/Arabic), иконками (Material Symbols),
**флагами стран** и **логотипами сервисов** — **без единого CDN**
(важно для аудитории в РФ, где CDN блокируемы).

## Запуск
```bash
python3 serve.py 8080          # затем открыть http://127.0.0.1:8080/Симбионт.dc.html
```
Рантаму нужен именно HTTP-сервер (компоненты грузятся через fetch), не `file://`.

## Что внутри
- `Симбионт.dc.html` — главный экран (весь UI: защита/узлы/маршруты/анализ/аккаунт/…).
- `ConnectionCore/Card/ListRow/Picker.dc.html` — компоненты.
- `support.js` — рантайм Design-Components (пропатчен: React/Babel из локальных файлов).
- `react*.js`, `babel.min.js`, `fonts/`, `fonts.css` — вшитые зависимости (offline).
- `flags/` — флаги всех стран ISO-3166 (`w40` PNG, flagcdn) — подхватываются по коду узла/языка.
- `icons/` — логотипы сервисов (Telegram, Discord, Steam, YouTube… — Simple Icons, SVG).
- `favicon.svg` — иконка вкладки (бренд-марка).
- `symbiont-strings.js`, `symbiont-i18n.js` — тексты и локализация.
- `vendor_assets.py` — скрипт, который переписал ссылки на CDN (шрифты/флаги/иконки) на локальные.

Все флаги/иконки скачаны один раз и лежат в репозитории; ни один экран не ходит в интернет
за ресурсами оформления. Языки китайский/хинди в списке используют системный шрифт-фолбэк
(Noto SC/Devanagari не вшиты из-за размера; основной UI — кириллица/латиница/арабица — вшит).

## Подключение к бэкенду
`symbiont-bridge.js` — мост оболочка ↔ бэкенд. Вёрстку (`renderVals`/шаблоны) не
трогаем: мост подменяет **данные** и **действия**.

- `window.SYM_API` — клиент REST `/v1/*` (манифест, ключи, аккаунт+PoW, колесо,
  биллинг, рефералы, устройства, поддержка) — см. `symbiont_build/backend/API.md`.
- `window.SYM_ENGINE` — абстракция VPN-движка; нативные обёртки внедряют свою
  реализацию, в браузере/веб-портале движка нет (каскад симулируется).
- `window.SYM_DATA` — «живые» данные (узлы из манифеста, тарифы); методы оболочки
  (`_nodes()` и др.) читают их первыми, откатываясь к демо-набору.
- `window.SYM_LIVE()` — надёжный признак живого режима (загружен манифест).

Режимы: **демо** (бэкенд недоступен или `live:false`) — оболочка работает как
раньше, байт-в-байт; **живой** — узлы/ключи/тарифы идут в сеть.

Конфигурация (до загрузки страницы, напр. в обёртке):
```js
window.SYM_CONFIG = { apiBase: 'http://127.0.0.1:8600', live: true };
// apiBase:'' → тот же origin (бэкенд отдаёт и статику). live:false → демо.
```
Локальный бэкенд для проверки: `cd symbiont_build/backend && python run_local.py`.

Уже подключено к бэкенду: список узлов (манифест), проверка ключа
(`/v1/key/check`), тарифы (`/v1/config/economy`). Клиент готов и для колеса,
биллинга, рефералов, регистрации (PoW) — их UI-склейка через `window.SYM_API`
делается по тем же принципам.
